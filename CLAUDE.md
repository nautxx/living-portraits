# Project notes: Living Portraits

Context for anyone (human or AI) picking up this project.

## Goal
Make Blizzard unit-frame portraits show a live 3D model with the idle "breathing"
animation, like the character screen, as a **companion addon** to BetterBlizzFrames (BBF).

## Key decisions
| Decision | Choice | Why |
|---|---|---|
| Fork BBF vs companion | **Companion addon** | BBF is "All Rights Reserved" (Bodify), so it can't be redistributed. Editing BBF directly is also wiped on every BBF update. |
| BBF dependency | `OptionalDeps` | Loads after BBF so we see its portrait resizing; still works without BBF. |
| Render approach | `PlayerModel` + `SetUnit()` + `SetPortraitZoom()` | Idle animation plays automatically. ModelScene (char screen) is heavier with no masking benefit. |
| Circle problem | **Model behind the ring + vignette** (option B) | Mask textures can't clip Model frames. First in-game test (inscribed square above the ring) showed hard square cut lines and a small face. Now the model sits under Blizzard's border ring, which hides its corners, and a vignette hides its straight edges. Rejected: tuning only (cut lines stay visible), square portrait art (big restyle). |
| Square style | **Default when BBF No Portrait / Pixel Border is on** | A square box can't have masking problems: the model fills it exactly. Box = BBF's 1px black pixel border recipe, anchored beside the bars (`UNITS[unit].bars` / `.side`), height = health top to mana bottom. Bigger box = taller bar stack (`stackExtra` large 10 / small 6, split `hpShare` 0.66 health / rest mana), so box and bars always align. A name row (`nameRow` large 12 / tot 9 / party 0, grouped by `UNITS[unit].row`) sits inside the box above the health bar: name + level on one line (every frame: name left, level right; ToT: no level), pinned via a `SetPoint` hook. Each pinned text's box shrinks to its text width (re-fit on `SetText`/`SetFont`/`SetWidth`, name capped short of the level): BBF gives names a fixed-width box and the player's `bbfName` ignores later `SetJustifyH` (stays centered), which indented the name with Blizzard's default font so BBF re-positioning doesn't move them (BBF's `bbfName` follows the real name automatically). Bar texts are re-centered vertically in their bars (`CenterBarTexts`; BBF's fixed y offsets were tuned for the thin bars). Falls back to circle where BBF still shows portraits. Boxes are parented to the **unit frame** (`UNITS[unit].frame`), never via the portrait: BBF's No Portrait mode reparents the player container and ToT/party portraits to a hidden frame. `LayoutBars` resizes health and mana (bar + BBF posFrame, which carries border/bg/mask), keeps each top edge fixed whatever its anchor point, moves mana down by the health growth (unless it's anchored to the health bar, e.g. ToT), and with `alignMana` shifts it to line up with the health bar on the box side (Blizzard offsets target/focus mana ~8px). Original anchor/heights are stored on the bar/text and restored by `RestoreBars` (circle style, disabled, extend 0). Out of combat only. |
| Rounded corners | **No: keep square** | Matches BBF's Pixel Border style exactly. Rejected: rounded box only (3D model corners can't be clipped, would peek past the curve) and rounded box + bars (needs custom border/mask art and takes over BBF's bar styling; fragile across BBF updates). |
| Touching Blizzard's portrait | **Hide only, never alter** | Hidden while the model shows, restored after. Never change its texture, alpha or color (Blizzard changes those itself). |
| Name | **Living Portraits** (folder `LivingPortraits`, was BBF Animated Portraits until v0.2.1) | "Living portraits" (the Harry Potter-style moving pictures) is unused by other WoW addons and sets it apart from Animated Blizzard Portraits / AlwaysFace. The BBF link lives in the description (`## Notes`), not the name. Rejected: "BetterBlizzPortraits" (reads as an official Bodify addon). In game the name is written as one word and styled like BBF's (`Living|cff00c0ffPortraits|r`: .toc title, settings entry, chat prefix), matching BetterBlizzFrames/Plates in the AddOns list; prose (README, CurseForge) keeps "Living Portraits" with the space for search. The settings list sorts on the raw name, so no leading color code. Slash `/lp`, `/livingportraits`, old `/bap` kept as alias. Renaming the folder means a fresh SavedVariables file: testers' settings reset. |
| Repo location | `~/GitHub/Main/living-portraits`, symlinked into AddOns as `LivingPortraits` | The beta client folder is temporary. One repo can feed multiple clients. |

## Architecture (Core.lua)
- `UNITS[unit]` describes each unit in one place: layout groups (`size` large/small, `offset`, `row`, `side`) and frame lookups (`frame()`, then `portrait`/`ring`/`bars`/`texts`, each taking the unit frame). **Add new units here** (and to `UNIT_LIST`, the fixed iteration order). Read lookups with `Lookup(unit, key)` / `UnitFrameOf(unit)`.
- `GROUPS` maps slash-command names (`player`, `target`, `focus`, `tot`, `party`) to units.
- **Layering (bottom to top)**, all created by `CreateLayers(unit)`:
  1. `bgFrame` (child of the unit frame root, level = container − 2): dark circle with its own mask (`TempPortraitAlphaMask`).
  2. `model` (child of root, level = container − 1): `PlayerModel` square sized `portrait × sizes[large|small].inset` (0.72). At 0.72 its corners stay under the ring's outer edge.
  3. Blizzard's container: the 2D portrait (hidden while active), our `vignette` texture (same sublevel as the portrait, `media/vignette.tga`) and the border ring art (one sublevel up). The ring covers the model's corners; the vignette is a **crisp circle edge** at the model's straight edges (`VIGNETTE_EDGE` = 0.72, scaled with inset, capped at portrait size), with a dark band out to the ring.
- Circle edge: `vignette.tga` is an inverted disc (clear inside, soft fade over the last 12% of the radius, opaque corners) sized exactly like the model, so it rounds off the model's square without extending past it. The dark area out to the ring is `bgFrame` (portrait-sized circle, under the ring). Earlier versions scaled a band past the model and it peeked outside the ring.
- Centering: `offsets[player|target|focus|tot|party]` nudge model, edge and backing together (`/lp offset`; defaults measured in game from a calibrate screenshot by fitting circles to the red edge and the ring's inner edge: player (-0.5, 0.6), target/focus (0.6, 0.3), ToT (-1.3, 2.2) later set to (-1.3, 0) from Jason's tuned settings, party unmeasured); `/lp calibrate` tints the edge red to line it up with the ring by eye (the edge and backing are the same color, so screenshots can't measure it).
- Containers below level 2 get raised to 2 while active (and restored): the target's container is level 0 in the BACKGROUND strata, so the model couldn't sit beneath it and drew on top (flat bottom, no circle edge). Found via `/lp debug`.
- **Layer relative to the ring's frame, not the portrait's.** On target/focus the ring (`TargetFrameContainer.FrameTexture`, LOW strata, level ~501) and the portrait (an unnamed child frame in the BACKGROUND strata, alongside other frames at levels 2-3, one of which draws a dark circle with BBF on) live in different frames. `UNITS[unit].ring` finds the ring; the circle edge is created on the ring's frame one sublevel beneath the ring texture, and model/backing sit at ring level -1/-2 in the ring's strata. On player/ToT/party the ring and portrait share a frame, so this is the same as before. Diagnosed with `/fstack`.
- While active, Blizzard's portrait is hidden (`Hide()`), and a `hooksecurefunc(portrait, "Show")` re-hides it if anything re-shows it. It's restored on deactivate only if it was shown before. Neither Blizzard nor BBF shows or hides these portraits (Blizzard only does for boss frames), so the risk of fighting them is low. **Side effect:** BBF spec/class icon portraits are covered while the model shows (model wins).
- The layers are no longer inside the unit frame, so they follow it via `container:HookScript("OnShow"/"OnHide")`, and `Refresh` checks `container:IsVisible()`.
- Alpha mirrors `portrait:SetAlpha` (party out-of-range fade) onto bg, model and vignette.
- **Settings migration:** saved settings win over new defaults, so when a default must change for existing installs, bump `SETTINGS_VERSION` and reset those keys in `MigrateSettings()`.
- Camera: `SetPortraitZoom(db.zoom)` + `SetCamDistanceScale(sizes[size].cam)` (0.85, lower = bigger face). `UNITS[unit].size` is `large` (player/target/focus) or `small` (ToT/party).
- `Refresh(unit)`: show or hide the layers and `SetUnit()` (a full model reload). Split into `RefreshSquare` / `RefreshCircle`. Events and container `OnShow` go through `QueueRefresh(unit)`, which coalesces requests into one refresh per unit on the next frame (one target change fires `PLAYER_TARGET_CHANGED`, `UNIT_TARGET` and often `UNIT_PORTRAIT_UPDATE`); slash commands and the ticker call `Refresh` directly. It hides when disabled, when BBF's `HasNoPortrait(unit)` is true (circle), or when the unit is missing or its frame hidden. Out of view range (not zoned in yet) or disconnected: circle hides; square keeps the full bar layout and shows an empty box (border + backing, model hidden, `ActivateSquare(..., empty)`) so its bars line up with the other frames. `UnitState`'s code includes the unit frame's visibility, so the ticker re-runs a refresh that happened while the frame was hidden (party frames during a dungeon loading screen).
- `Tick()` (every 0.5s) compares `UnitState(unit)` (GUID + a visible/connected code, two plain values: no string built per tick) with the last refresh (`StateChanged`/`MarkState`) and refreshes only on change. This covers changes with no reliable event: ToT/FoT swaps, party members entering or leaving view range.
- `Safe(v)` drops "secret" values (`issecretvalue`) so comparisons and concatenation never error. Battlegrounds make far more values secret (enemy health, health text and its position, bar fill alpha): any value read back from a Blizzard frame needs `Safe`/`IsSecret` before math or `==`.
- Events: `PLAYER_ENTERING_WORLD` (0.5s delay so BBF finishes resizing; starts the ticker), `PLAYER_TARGET_CHANGED` (target + ToT), `PLAYER_FOCUS_CHANGED` (focus + FoT), `UNIT_TARGET` (ToT/FoT), `GROUP_ROSTER_UPDATE` (party), `UNIT_MODEL_CHANGED`, `UNIT_PORTRAIT_UPDATE`, `UNIT_CONNECTION`.
- Target bar grow (`StartGrow`/`GrowStep`, `/lp grow`, `/lp growtime`, trace with `/lp grow debug`): post-hooks `TargetFrame:Update()` and `FocusFrame:Update()` (`HookGrowUpdates` → `GrowBars(unit)`; Blizzard calls them on target/focus change, login and `UNIT_TARGETABLE_CHANGED`, after setting the bar values; only the target frame registers `PLAYER_TARGET_CHANGED`, so the focus doesn't replay on target swaps). Target-of-target is left out on purpose: it changes many times a second in fights, so a grow would flicker, and Blizzard refreshes it on a timer with no clean new-unit trigger. For `growTime` seconds an overlay `StatusBar` (`bar.bapGrowBar`, same strata/level, fill one sublevel above Blizzard's so bar texts stay on top) mirrors the bar's live min/max/value and the fill's look (`CopyBarStyle`, every frame, mask list rebuilt only when the fill's masks change so nothing is allocated per frame: texture/atlas, vertex color RGB only (its alpha follows our `SetAlpha(0)` and hid the overlay), desaturation, blend, mask textures (Blizzard's `HealthBarMask`/`ManaBarMask` clip the fill's end; unmasked, the overlay grew past it), because BBF class colors are a desaturated fill + tint, sometimes set on the fill texture directly) while its **width** eases 0 → bar width; Blizzard's fill is hidden with `SetAlpha(0)` and restored after (only if still 0, or if its alpha reads back secret, which happens in battlegrounds; `EndGrow` removes the grow before touching anything so an error can't repeat every frame). Instances (Wailing Caverns) also make the bar's style secret (`GetOrientation` errored on compare): `BarReadable` checks width, orientation, reverse fill, the fill's texture/atlas/desaturation/blend/draw layer and masks, and the grow is skipped or ended when any is secret. Width does the lerp because values can be secret: tainted code can't do math on them and `C_CurveUtil` `AddPoint` only takes secrets when untainted, but `SetValue`/`SetMinMaxValues` accept them. Rejected: `SetValue(v, ExponentialEaseOut)` on Blizzard's bar (Blizzard's immediate re-sets cancelled it; grew only once in game) and growing from our own `PLAYER_TARGET_CHANGED` (can run before Blizzard's handler, animating to the old target's value).
- SavedVariables: `LivingPortraitsDB` (defaults merged on `ADDON_LOADED`).
- **Talent build** (`UpdateBuild` → `UpdateBuildFor(unit)` for `BUILD_UNITS` player + target + focus, `/lp build`, `db.showBuild`): points per tree ("2/8/0"). Square style with a name row only (`BuildVisible`). **Tall portraits** (`db.tallPortraits` per group `{ player, target, party }`, target covers focus; `TALL_GROUP` maps units; `/lp tall [player|target|party]`, no group flips player + target together; three panel checkboxes; all on by default (party since Jason's settings became the defaults); v11 migration turns the old boolean into the table with party off, so upgrades keep their look; ToT stays square. Jason chose per group over one switch or per frame. Party has no name row or build: its box just grows up by the same line, beside the name above its bars): the build gets its own fixed `BUILD_LINE` 9 px line above the name (`BuildLine(unit)`); `PlaceSquare` grows the box upward by it, so the box is a taller rectangle while the bars keep their size and spot. The line is reserved even with nothing to show (NPC targets): bars can't relayout in combat. Tall off: square box, build right-anchored to the level's left (`bapInline`; only then does the name's max width subtract it). Jason chose fixed presets over a height slider, the line above the name over a row under the bars (would push into the ToT frame) and over squishing the bars. `buildTexts[unit]` are FontStrings on the unit frame, level's font −2, grey. Camelot talents are C_Traits with 3 node groups per tree: `ReadBuild(configID)` maps `C_Traits.GetGroupCurrencyInfo` spent per `traitNodeGroupID` onto `GetGroupDisplayInfoByTreeID` order, filling 0 for trees the game leaves out. Own build: `C_ClassTalents.GetActiveConfigID()`, cached in `ownBuild` until `TRAIT_CONFIG_UPDATED`. Others: `NotifyInspect(unit)` (target or focus) → `INSPECT_READY(guid)` → `Constants.TraitConsts.INSPECT_TRAIT_CONFIG_ID` (verified in game: the server sends inspect talents). Cached per GUID for the session; one inspect at a time (a second `NotifyInspect` replaced the pending one and its reply was dropped), a player with no reply within `INSPECT_TIMEOUT` waits `NO_REPLY_WAIT` 30s so the other frame gets a turn, inspects spaced `INSPECT_GAP` 1.5s, none in combat, none while Blizzard's InspectFrame is open, retried by the ticker; only our own GUID's reply is used.
- **ToT clearance** (`ClearTot(unit)` after each target/focus or ToT/FoT layout, `RestoreTot` on hand-back): our taller target/focus stack can run into its target-of-target. Edit Mode's *small* focus frame (`FocusFrame:SetSmallSize`: focus scaled 0.75, focus-target scaled back up and anchored `TOPRIGHT` to the focus's `BOTTOMRIGHT` +20/+8) made the focus-target overlap the focus box. The ToT is nudged down by the measured overlap (screen space: our box/mana bottom vs the ToT frame's or its own box's top, skipped when side by side) + `TOT_CLEARANCE` 2, always measured from the anchor Blizzard/BBF gave it (a changed anchor becomes the new base); `SetSmallSize` is hooked to re-run. Out of combat only (secure unit button).
- **Border thickness** (`db.borderSize` 1 thin / 2 medium / 3 heavy, a dropdown; Jason found 4 too much; `BorderSize()`, `/lp bordersize`): `LayoutEdges(edges, frame, size)` sizes and anchors our box edges and BBF's bar edges (around `bar.BBFPositionFrame`); top/bottom span the corners and the sides fit between, so each corner is drawn once (BBF's own geometry overlaps them, which looked darker at partial opacity). Shared lines follow the thickness (`SharedLine()` = size when opaque; `BoxGap()`), and the ToT clearance adds it. `RestoreBorders` re-applies BBF's exact 1px geometry (`bbf = true`).
- **Border color** (`db.borderColor` ARGB hex like the Settings color swatch, default `ff000000`; `db.borderAlpha`; `/lp bordercolor RRGGBB`, `/lp borderalpha`): `ApplyBorders` colors our box edges (`sq.edges`) and BBF's bar edges (`bar.BBFBlackBorder`: BBF sets them black once at creation and never again, so runtime recoloring sticks; verified in `forever/modules/noPortrait.lua`). Shared lines (box/bars at `squareGap` 1, health/mana at `barSpacing` 0) would draw twice and look darker below full opacity, so the bar edge on the box side and mana's top edge are hidden there. `RestoreBars` gives BBF its black, fully shown edges back (`RestoreBorders`). Below full opacity the shared 1px slot itself goes (`SharedLine()` 0: mana starts at health's bottom, `BoxGap()` one less): BBF's fills overhang their bordered areas by 1px differently per frame (`/lp debug`: bar h 18 vs posFrame h 17; on the player the health fill covered the slot, on the target it didn't), so a see-through line showed the world on some frames only. Closed up, the faint line is drawn over the bars on every frame.
- **Status icons** (`StatusIcons`, player only): BBF's No Portrait mode moves `PlayerFrameContentContextual.AttackIcon` (combat) and `PlayerRestLoop` (resting Zzz) into the old portrait spot, which is now our box (on the face). Blizzard shows only one at a time, so `LayoutNameRow` pins both just after the shown name (`bbfName` or name; the Zzz frame is scaled 0.5, hence `REST_X`/`REST_Y`, tuned in game) and reserves `STATUS_ICON_ROOM` in the name's max width; restored with the name row.
- **Elite icon** (`EliteIcon`, `UNITS[target/focus].elite` → `TargetFrameContainer.BossPortraitFrameTexture`): BBF's No Portrait mode makes it a 15px nameplate elite icon centered on the health bar's top-right corner (`noPortrait.lua` ~837, re-set on each target update), which is now on the name and our box. `PlaceElite` places it by `db.eliteIcon` (dropdown, `/lp eliteicon`): `top` (default) / `bottom` = centered on the box's outer top/bottom corner, `center` = box bottom middle, `level` = beside the level (or the "??" skull when that shows instead) on the side facing the name, `hidden` = alpha 0 (`SetEliteHidden`, only undone if we set it). Jason chose presets; with the gold border carrying the signal, the default moved off the name row. Skull Show/Hide/SetShown are hooked to re-place it. Only `level` reserves `ELITE_ROOM` in the name's max width and pushes the inline build (tall off) past it (`EliteInRow`). The first layout runs before the box exists and falls back to `level`; RefreshSquare's next-frame LayoutNameRow puts it on the box. The icon draws above our box and model: BBF reparents it to `frame.noPortraitMode`, a HIGH-strata frame (`noPortrait.lua` ~742). **Skull** (`UNITS[target/focus].skull` → `TargetFrameContentContextual.HighLevelTexture`): BBF puts it at `CENTER, frame RIGHT -91, 17` (our box's corner); pinned in the level's spot, and the name's room counts `SKULL_WIDTH` when it shows. **Elite border** (`db.eliteBorder`, `/lp eliteborder`, on by default; `EliteColor` via `UnitClassification`, Safe'd): the box border and the health/mana borders take `db.eliteColor` (elite/worldboss, default gold `ffffc71a`) or `db.rareColor` (rare/rareelite, default silver `ffc7ccdb`), all one color as Jason asked, because the small icon alone was too easy to miss. Both are ARGB hex like `borderColor` (`HexRGB`), with color swatches in the panel and `/lp elitecolor` / `/lp rarecolor RRGGBB`; the border opacity setting still applies. The elite icon takes the same color (`TintElite` in `ApplyBorders`, so it also updates in combat: desaturate + vertex color; the atlas is bronze and clashed with the gold border), undone by `RestoreElite` or when the border is off/normal unit. All restored by `RestoreBars` and when the name row is off.
- **Party icons** (`LayoutPartyIcons`, `UNITS[party].icons` → `PartyMemberOverlay.RoleIcon/LeaderIcon/GuideIcon/Disconnect`): BBF's No Portrait mode put the role icon on our box's top-right corner and the disconnect icon over box and bar. Square style pins role just left of the party name, leader/guide left of the role ("[role][crown] Name"), and the disconnect icon in the box's center; restored by `RestoreBars`. The name (`partyName` lookup, `bbfName` if shown: BBF anchors it BOTTOM to `frame.Texture` TOP in a fixed 76-wide centered box) is pinned at its own anchor with its box fitted to the text (capped at BBF's width), so "left of the name" is the text's edge. Not a `texts` lookup: party has no name row, and `LayoutNameRow` would restore those. Right of the bars was rejected (BBF party castbars sit there). A leader with no role shows a gap where the role icon would be.
- **Mirror target text** (`db.mirrorTarget`, `/lp mirror`, on by default; `Mirrored(unit)` = setting on and `UNITS[unit].side == "RIGHT"`, i.e. target and focus): `LayoutNameRow` pins name/bbfName right (portrait side) and the level left (outer edge); the build goes above the name on the right, or with tall off between the level and the name. Symmetry with the player frame, asked for by Jason.
- **Surnames** (`UpdateSurnames`, `db.hideSurname`, `/lp surname`, on by default): Camelot's `UnitName(unit)` returns (first name, surname) (on retail the second value is the realm), and Blizzard's frames join them with `CHARACTERNAME_SURNAME_SEPARATOR` (a space; a C constant, read at runtime). A `SetText` post-hook (`StripSurname`) on each name text of `SURNAME_UNITS` (player, target, focus, ToT/FoT, party; incl. BBF's `bbfName`) removes just " <surname>", so BBF's color codes/prefixes survive; full/short text kept to restore when turned off. The ticker only hooks name texts as they appear (BBF creates `bbfName` after us; `HookName` strips its current text once); after that the hook does the work, so nothing is re-stripped per tick. Strip/restore of all names (`UpdateSurnames(true)`) runs after every `RefreshAll`. Not touched: chat, nameplates, raid frames.
- **Old install** (`CheckOldAddon`, on `PLAYER_ENTERING_WORLD`, once per session): if the pre-rename `BBF_AnimatedPortraits` is still loaded, both addons would draw models and lay out bars on the same frames. Prints a chat note and shows a popup that disables it (`C_AddOns.DisableAddOn` + `ReloadUI`, Blizzard's own pattern from its addon-performance popup).
- Slash: `/lp`.
- **Settings panel** (`BuildOptions`, Options → AddOns, `/lp options`): main page = General, Camera (zoom, both styles), Target bars, BetterBlizzFrames; sub-pages **Square Style** and **Circle Style** (`Page(name)` → `Settings.RegisterVerticalLayoutSubcategory`, falls back to a header on the main page) hold each style's settings, including its camera distance (square: one `sizes.square.cam` for every box; circle: `sizes.large/small.cam`). Jason asked for the split after the large/small distance sliders turned out to do nothing in square style. Settings API proxy settings (`Settings.RegisterProxySetting`) over `db` paths (`Path(keys)` gives get/set/default), so there's no second copy of the settings. Setters call `QueueRefreshAll()` (sliders fire continuously). `RefreshAll` ends with `AfterRefreshAll` (talent build + surnames), so panel, slash and BBF re-layouts all apply those right away. Slash changes call `NotifyOptions()` so the panel shows them. Slash on/off and number settings are tables (`SLASH_TOGGLES`, `SLASH_NUMBERS`). Variables are prefixed `BAP_`. Built on `ADDON_LOADED`; skipped when the client has no `Settings` API.
- **BBF setup** (`ApplyBBFSetup` / `UndoBBFSetup`, panel buttons, `/lp bbfsetup` / `bbfundo`): writes `BBF_SETUP` (No Portrait + Pixel Border on, party-only and per-frame skips off: what `BBF.HasNoPortrait` checks) into `BetterBlizzFramesDB` at runtime, never BBF's files. The first apply backs up the old values in `db.bbfBackup` (`NO_VALUE` marks keys BBF never saved); Undo restores them; `/lp reset` keeps the backup. BBF reads these on load, so both offer a Reload UI popup. Jason chose to set only the mode itself, not his own BBF look (fonts, textures, ToT placement).

## Blizzard / BBF frame paths (WoW Forever beta, internal name "Camelot", client 1.60.1.70374)

Verified against Blizzard's UI source: `github.com/Gethe/wow-ui-source`, branch **`forever`** (same build as the client). Camelot loads the Mainline ("Family") unit-frame XML.
Also exported locally from the client (`exportInterfaceFiles code`) to `_classic_beta_/BlizzardInterfaceCode/`. The unit-frame files match the mirror byte-for-byte (ignoring CRLF).

| Unit | Portrait (layer) | Mask | Border art (layer) |
|---|---|---|---|
| player | `PlayerFrame.PlayerFrameContainer.PlayerPortrait` (BACKGROUND 1) | `PlayerPortraitMask` | `FrameTexture` (BACKGROUND 2) |
| target / focus | `TargetFrame/FocusFrame.TargetFrameContainer.Portrait` (BACKGROUND 1) | `PortraitMask` (CircleMask) | `FrameTexture` (BACKGROUND 2) |
| targettarget / focustarget | `TargetFrame/FocusFrame.totFrame.Portrait` 37×37 (BACKGROUND 1) | `PortraitMask` (CircleMask) | `FrameTexture` (BACKGROUND 2) |
| party1–4 | `PartyFrame.MemberFrame1..4.Portrait` (BACKGROUND) | `PortraitMask` (CircleMask) | `Texture` (ARTWORK) |

**Findings that affect the design:**
- The border art sits only **one sublevel above** the portrait on player, target and ToT, so a texture at "portrait sublevel + 1" shares the border's sublevel (undefined draw order). **Fixed** by moving our layers into a separate holder frame with its own mask.
- Blizzard changes the portrait itself: party portraits fade with `SetAlpha` when out of range (`PartyMemberFrame.lua:399`) and get `SetVertexColor` tints (`:671-677`). The target portrait is greyed when tapped (`TargetFrame.lua:329`) and reset to alpha 1 (`:156`). **Don't hide the portrait via alpha**: Blizzard will overwrite it.
- Party member frames come from a frame pool (`PartyFrame.lua:56-59`) and are assigned as `MemberFrameN` on init.

**Shared borders:** box↔bars `squareGap` 1 and health↔mana `barSpacing` 0 make adjacent 1px borders overlap into one line. Mana's vertical position is measured after layout and corrected (`bapDY`), which also closes BBF's ToT health/mana gap; mana's border width is forced to health's (`alignMana`).

**When to hand layout back to BBF:** only when the user turns something off (disabled, unit toggled off, circle style, `namerow 0`). Transient states (no target, frame hidden) just hide the box and keep bars/names pinned; restoring there let BBF's name/level positions stick after target switches (diagnosed via `/lp debug`).

**NPCs with no power:** Blizzard hides the mana bar, but BBF (pixel border) reparents the mana posFrame/border/background to `frame.noPortraitMode` so an empty mana slot stays visible. `GetBarFrames` treats a visible slot as the mana row; if BBF hides the slot too (hide-mana option), health takes the whole stack (`LayoutBars` no-mana path).

**BBF runtime re-layouts:** BBF rebuilds parts of its layout when settings change (fonts → `BBF.SetCustomFonts`, names → `ApplyNameLayout(s)`, bar text → `UpdateNoPortraitText`, …). `HookBBF()` hooks those (`BBF_RELAYOUT_FUNCS`) and queues a debounced `RefreshAll`. Add new ones there if another BBF setting knocks the layout out.

BBF code that touches portraits (read only, for compatibility):
- `forever/BetterBlizzFrames.lua` ~5143–5164: resizes portraits and masks (player 61, target/focus 56).
- `forever/modules/classicFrames.lua` ~343, ~660: the Classic Frames mode repositions portraits.
- `forever/modules/noPortrait.lua`: `BBF.HasNoPortrait(unit)`; we skip when true.
- `BBF.SpecPortraits()` (~5528) and `forever/modules/healer.lua` `UpdateSecretPortrait`: spec and healer icon portraits. **Open question:** should icons win over the model?

## Commit messages

Put a Conventional Commits prefix on every commit title: `type: short imperative summary`.

- `feat`: new capability or behavior (a new unit frame, a new slash command, a new option)
- `fix`: bug fix
- `chore`: maintenance with no user-visible behavior change (TOC bumps, config, cleanup, license)
- `docs`: README, CLAUDE.md or comment-only changes
- `refactor`: code restructuring with no behavior change
- `test`: test-only changes
- `style`: formatting or whitespace, no logic change
- `perf`: performance improvement
- `revert`: reverts a previous commit

After the colon: lowercase, imperative mood ("add", not "added" or "adds"), no trailing period, ideally under ~70 characters. Example: `feat: add animated portraits to target and focus frames`.

No `Co-Authored-By` or other AI attribution lines in commit messages (they made Claude show up as a repo contributor; removed from history on 2026-10-15).

When a commit touches only one thing, the title alone is enough, so skip the body. When a commit bundles several distinct changes, add a blank line after the title and a short bullet per change:

```
feat: add animated portraits to target and focus frames

- add target/focus entries to GetPortraitInfo()
- refresh on PLAYER_TARGET_CHANGED and PLAYER_FOCUS_CHANGED
- document new frame paths in CLAUDE.md
```
